# Zomato UC - Deployment Plan (Production-Level Testing on Free Cloud Tiers)

This document outlines a comprehensive deployment strategy to host the Zomato UC application (Angular frontend + Spring Boot microservices) in a production-like environment for testing, utilizing generous free tiers provided by cloud platforms.

## 1. Architecture Overview

- **Frontend:** Angular Application (`frontend/web-ui`)
- **Backend:** Spring Boot Microservices (`api-gateway`, `discovery-server`, `user-service`, `restaurant-service`, `ai-service`, `location-service`, `recommendation-service`, `review-service`, `search-service`)
- **Databases/Cache:** Microservices dependencies (e.g., MongoDB, PostgreSQL, Redis)

## 2. Recommended Free Cloud Providers

Given that Java Spring Boot microservices are resource-intensive (especially RAM), traditional free tiers like AWS t2.micro (1GB RAM) are insufficient to run 8+ microservices simultaneously.

### The Ultimate Free Backend Solution: Oracle Cloud Infrastructure (OCI) Always Free
Oracle Cloud provides the most generous free tier in the industry for compute:
- **Compute:** Up to 4 ARM Ampere A1 Compute instances with a combined total of **24 GB RAM** and **4 cores**.
- This is more than enough to run the entire backend stack (all microservices + databases) using Docker and Docker Compose.

### Frontend Hosting: Vercel or Netlify
- **Vercel / Netlify:** Best-in-class for Angular apps. Global CDN, automatic CI/CD from GitHub, and free SSL.

### Managed Databases (Optional, if not self-hosting on Oracle)
- **MongoDB:** MongoDB Atlas (M0 Free Cluster - 512MB storage).
- **PostgreSQL:** Supabase or Neon (Generous free tiers).
- **Redis:** Redis Cloud (30MB free tier).

## 3. Deployment Strategy

### Phase 1: Preparation (Dockerization)
Ensure all services are fully Dockerized. The project utilizes a `docker` directory for infrastructure.
1. **Dockerfile:** Ensure each Spring Boot service has a highly optimized `Dockerfile` (e.g., using multi-stage builds and Alpine/Distroless JRE images to save RAM).
2. **Docker Compose:** Create a `docker-compose.prod.yml` that orchestrates all backend services, API Gateway, and Discovery Server.
3. **Environment Variables:** Externalize configuration (DB URLs, API keys, AI service keys) using `.env` files. Ensure `application.yml` files are configured to read from these environment variables.

### Phase 2: Frontend Deployment (Vercel)
1. Push the `frontend/web-ui` code to a GitHub repository.
2. Log in to [Vercel](https://vercel.com/) and create a new project.
3. Import the GitHub repository.
4. **Build Settings:** Vercel automatically detects Angular.
   - Build Command: `ng build --configuration production`
   - Output Directory: `dist/web-ui/browser` (verify exact path generated by Angular v17/v18).
5. **Environment Variables:** Add the production API Gateway URL (e.g., `API_BASE_URL=https://api.your-oracle-domain.com`).
6. Deploy. Vercel provisions a free `.vercel.app` domain and handles SSL automatically.

### Phase 3: Backend Deployment (Oracle Cloud)
1. **Sign Up:** Register for an Oracle Cloud Free Tier account.
2. **Provision Instance:**
   - Create a new Compute Instance.
   - Select **Ampere A1 (ARM)** architecture.
   - Allocate **4 OCPUs** and **24 GB RAM**. (You can provision one large instance or two smaller ones).
   - Select Ubuntu 22.04 or 24.04 as the OS.
   - Download the SSH key pair.
3. **Configure Networking (VCN):**
   - Open necessary ports in the Oracle Cloud Security List for your Virtual Cloud Network (VCN): `80` (HTTP) and `443` (HTTPS).
4. **Server Setup:**
   - SSH into the instance: `ssh -i <private_key> ubuntu@<public_ip>`
   - Install Docker and Docker Compose:
     ```bash
     sudo apt update && sudo apt install docker.io docker-compose -y
     sudo usermod -aG docker $USER
     ```
5. **Deploy Services:**
   - Clone the backend repository or transfer the `docker-compose.prod.yml` and build context.
   - Configure the `.env` file on the server with production DB credentials and keys.
   - Build and start the services:
     ```bash
     docker-compose -f docker-compose.prod.yml up -d --build
     ```
6. **Reverse Proxy & SSL (Nginx / Caddy):**
   - It is highly recommended to set up a reverse proxy (like Nginx or Caddy) in a Docker container to route external traffic on port 80/443 to the Spring Cloud API Gateway.
   - Use Certbot (Let's Encrypt) with Nginx, or use Caddy which provisions SSL automatically, ensuring secure `https://` communication from the Vercel frontend.

## 4. CI/CD Pipeline (GitHub Actions)

To achieve production-level testing, automate the deployment to simulate a real-world pipeline:

### Frontend CI/CD
Vercel handles this automatically out-of-the-box on every push to the `main` branch.

### Backend CI/CD (GitHub Actions to Oracle Cloud)
Create a `.github/workflows/deploy-backend.yml`:
1. Trigger on push to `main` (filtered by paths: `backend/**`).
2. SSH into the Oracle instance using a GitHub Action (e.g., `appleboy/ssh-action`) utilizing secrets for the SSH key and host IP.
3. Pull the latest code from GitHub.
4. Run `docker-compose -f docker-compose.prod.yml up -d --build` to restart updated services.

## 5. Monitoring & Maintenance
- **Portainer:** Deploy a free Portainer CE container on the Oracle instance to easily monitor Docker containers, view logs, and manage resource usage via a web UI.
- **Resource Constraints:** Even with 24GB RAM, tuning the JVM memory allocation for each microservice (e.g., `-Xmx512m`) in the Docker compose file is critical to prevent out-of-memory (OOM) errors.
- **Log Aggregation:** Viewing logs via Portainer or `docker logs -f <container_name>` is sufficient for this testing tier.
