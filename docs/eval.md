# Zomato AI Concierge - Evaluation Strategy

This document outlines the evaluation framework for the Zomato AI Concierge platform. The evaluation covers both the multi-agent AI backend (as defined in `architecture.md`) and the frontend enhancements like the Occasion Selector and Compare Functionality (as defined in the `implementation_plan.md`).

## 1. AI Output Quality & Grounding

Evaluating the core responses generated by the LLMs (Review Analysis Agent, Explanation Agent, and the new "AI Verdict" in the Compare feature).

### 1.1 Hallucination & Grounding Metrics
- **Metric:** Factual Consistency Score (e.g., using DeepEval or Ragas).
- **Evaluation:** Does the "AI Verdict" in the Compare view only mention attributes (dishes, vibes, prices) that actually exist in the underlying Elasticsearch and PostgreSQL databases?
- **Methodology:** Automated unit tests running offline datasets of 100 benchmark comparisons. Comparing the LLM output against a strict JSON schema of facts for the selected restaurants.

### 1.2 Intent Parsing Accuracy
- **Metric:** Intent Classification Accuracy / Slot Filling F1 Score.
- **Evaluation:** When a user clicks the "🍝 Date Night" pill, does the Intent Agent reliably map this to `vibe=romantic, price=mid-to-high, lighting=dim`? 
- **Methodology:** A golden dataset of 500 user utterances (and simulated pill clicks) evaluated for precise parameter extraction.

## 2. System Performance & Latency

Multi-agent architectures can introduce significant latency. Performance evaluation is critical.

### 2.1 End-to-End Latency
- **Metric:** Time to First Byte (TTFB) and Total Generation Time.
- **Evaluation:** 
  - How long does it take from clicking an Occasion Pill to rendering the first set of restaurant recommendations? (Target: < 2 seconds).
  - How long does it take for the `/compare` route to generate and display the side-by-side matrix *and* the AI Verdict? (Target: Matrix < 1s, AI Verdict stream < 3s).
- **Methodology:** Distributed tracing (e.g., Jaeger/Zipkin) integrated with Spring Boot across the microservices (search-service, review-service, ai-service).

### 2.2 Agent Fallback Rate
- **Metric:** Percentage of requests that experience partial agent failure.
- **Evaluation:** How often does the Social Recommendation Agent or Location Agent time out, forcing the Orchestrator to proceed with partial context?
- **Methodology:** Log analysis via Elasticsearch/Kibana dashboards monitoring Spring AI tool-calling execution times.

## 3. Retrieval & Recommendation Relevance

Evaluating how well the vector database (pgvector) and search engines (Elasticsearch) surface the right candidates.

### 3.1 Ranking Quality
- **Metric:** Normalized Discounted Cumulative Gain (NDCG) and Mean Reciprocal Rank (MRR).
- **Evaluation:** Does the Ranking Agent correctly weight the signals? For instance, if the Budget Agent signals a strict budget, are cheaper restaurants ranked higher regardless of raw popularity?
- **Methodology:** A/B testing recommendation lists against baseline Elasticsearch BM25 queries.

### 3.2 Semantic Search Accuracy
- **Metric:** Recall@K.
- **Evaluation:** When searching for "quiet place for reading," does the Recommendation Service retrieve venues where reviews frequently mention "quiet" and "reading"?
- **Methodology:** Human-in-the-loop (HITL) evaluation of the top 5 results for 50 complex semantic queries.

## 4. UI / UX Engagement (Frontend Enhancements)

Evaluating the success of the new features outlined in the implementation plan.

### 4.1 Feature Adoption Rates
- **Metric:** Click-Through Rate (CTR) / Usage Percentage.
- **Evaluation:** 
  - What percentage of user sessions utilize the Occasion Selector pills versus typing a manual query?
  - What percentage of users select 2+ items to trigger the Compare Floating Action Button (FAB)?
- **Methodology:** Frontend product analytics tracking (e.g., Mixpanel, Google Analytics).

### 4.2 Task Success Rate
- **Metric:** Compare Completion Rate.
- **Evaluation:** Once a user lands on the `/compare` route, do they proceed to book a table or navigate to a specific restaurant detail page? High bounce rates on the compare page indicate the table or AI Verdict is not helpful enough.
- **Methodology:** Funnel analysis from Home -> Select Items -> View Compare -> Book/Navigate.

## 5. Continuous Evaluation (CI/CD)

- **Regression Testing:** Every PR to the `ai-service` must run against a test suite of 50 "golden" prompts to ensure changes to the Spring AI orchestration do not degrade Intent or Ranking accuracy.
- **LLM Cost Monitoring:** Track token usage per feature. The Compare feature's "AI Verdict" might consume significantly more tokens than a standard search. Cost per API call should be tracked as a primary business metric.
